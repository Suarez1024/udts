# MySQL 迁移到 ClickHouse

数据集成的基本要求与数据传输完全相同， 具体信息请参考[MySQL 迁移到 ClickHouse 数据迁移说明](/udts/type/mysql_source/mysql2clickhouse)

## 迁移内容

数据集成当前只迁移 Database、Table 及其数据，不迁移视图(View)、函数(Function)、存储过程(Procedure)等其它内容。

## 功能说明

### 执行顺序
- 数据源按添加显示顺序排序，前面的任务优先执行。
- “增量任务”与“全量+增量任务”均为并行执行。
- 当某一数据源的任务类型为全量任务时，只有该全量任务完成后才启动后续任务。
- 全量任务完成后，不支持重新启动。

### 是否保留目标库的原数据
目前只支持保留目标库的原数据。

### 数据冲突解决策略
数据冲突时，由目标库表引擎确定处理方式。
- ReplicatedMergeTree：保留重复数据。
- ReplicatedReplacingMergeTree：默认保留最新插入的数据，指定版本列时，根据版本列确定。

### 创建库表方式
选择“自动创建库表”时，要求待迁移的库表必须有主键或唯一索引，如果不满足要求，请选择“手动创建库表”，并在目标库中提前创建待迁移库表。

### ETL
- 填写ETL信息时，如果勾选了数据库或者表，则必须填写映射名，如果不需要进行映射，默认填写与数据源相同的库名/表名
- 填写ETL信息时，如果勾选了库，未选择表，则迁移该库下的所有表
- 目前只支持单库迁移

## 功能限制
- 数据集成任务暂不支持DDL语句，因为DDL语句可能会改变目标数据库的表结构，破坏ETL功能。
